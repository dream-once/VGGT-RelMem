## 2. 项目里真正值得讲清楚的技术内容

**几何契约与稳健 lifting。** SAM 必须接收与 VGGT pointmap 相同 resize/crop/pad 后的图像，不能对原图分割后随意 resize mask。当前适配器的 pointmap 留在 submap 坐标，名为 `world_from_camera` 的历史字段可能保存非刚性的投影变换；lifting 做齐次乘法并除以 w，不能一概当普通 SE(3)。真正用于视角和方向的刚性 anchor pose 另行保存。`confidence_maps` 实际是上游按置信度分位数生成的二值有效掩码，原始置信度另存；不要说在此处学到了连续深度不确定性。

**多视角关联的精度与召回取舍。** A1 对通过几何 gate 的边做连通分量，A–B、B–C 能间接合并 A–C。A2 要求两个簇所有跨簇 pair 都通过 gate。有效 gate 是类别兼容、质量下限，以及中心距离或 AABB 重叠；形状分数等还影响合并顺序。至少两个不同帧才晋升永久对象。最终没有 semantic embedding，同 task 类别又恒定，所以实际关联证据来自几何与质量。

**融合可能把中心移出物体。** 当前 fused center 是观测质量加权平均；不是联合优化三维表面，fused OBB 是各观测 OBB 角点的轴对齐外包。后续 PE 扩展是在已经选定的 object 内选择一个代表观测中心，不是 PE 重新聚类或重新选择整个场景的物体。

**实验设计有明确反例。** Apartment 物体严格定位 2/18→2/18，Cubicle 5/18→7/18；A2 在 Cubicle 的总体 pairwise F1 还低于 A1。能解释负结果、分清候选缺失与排序失败，比只背“提升 11.11 个百分点”更有说服力。

**置信度还只是工程分数。** observation quality 是检索分数、SAM 分数、有效点比例的几何平均；对象置信度用 `1 - ∏(1 - quality)` 累积。重复且相关的观测也会提高这个分数，因此它不是“物体正确概率”。`LogisticCalibrator` 类虽然存在，正式关系推理没有调用它的 fit / predict_proba，六维 feature 也未接入正式预测。

## 3. F1 的完整核验与新跨帧统计

从旧 association_benchmark 的逐 pair 记录重新计数，预测与标签均未改变：

| 统计口径 | Apartment A1 / A2 | Cubicle A1 / A2 |
|---|---:|---:|
| 全部可评配对：原简历口径 | 85.29% / 88.14%（53 pairs） | 93.47% / 91.56%（1,375 pairs） |
| 只保留不同帧观测配对 | 90.00% / 90.91%（47 pairs） | 93.31% / 91.38%（1,079 pairs） |

在原口径下，Cubicle A2 将 FP 从 137 降到 73，但 FN 从 0 增到 91；precision 从 87.75% 升到 92.42%，recall 从 100% 降到 90.72%。这正好支持“complete-link 更保守、减少误合并但增加漏合并”的解释，不能支持“A2 总体优于 A1”。

F1 的分母由有可评观测的 pair 构成，失败任务不会凭空产生 pair。因此 F1 很高并不意味着全场景物体定位很好。对齐误差扩张参与关联标签生成，也会影响其解释。

## 4. 关系拒答现状：先看分母，再看百分比

| 原冻结协议 | Apartment | Cubicle |
|---|---:|---:|
| 正例 / 反向关系负例 | 136 / 136 | 149 / 149 |
| 实际输出答案 / 全部查询 | 39/272 | 91/298 |
| 正例严格双端正确 / 全部正例 | 0/136 | 17/149 |
| 正例容差双端正确 / 全部正例 | 16/136 | 72/149 |
| 负例拒答 / 全部负例 | 136/136 | 147/149 |
| 双端容差定位正确且按关系冲突拒答 / 全部负例 | 14/136 | 67/149 |
| 严格错误答案 / 实际回答 | 39/39 | 74/91 |
| 容差错误答案 / 实际回答 | 23/39 | 19/91 |

严格：预测 target 与实际使用的 reference 中心都在对应 GT OBB 内。容差：OBB 每个轴的半径额外加上场景配准 RMSE；Apartment 约 13.63 cm，Cubicle 约 2.99 cm。它是配准敏感性分析，不是统计置信区间，也不能用来证明严格定位准确。

注意，`67/149 = 44.97%` 的分母是 **全部负例**。如果真的条件在预测已选到双端容差定位正确的负例子集，数字是 `67/67`；Apartment 是 `14/14`。这些 100% 来自较小且经过筛选的简单反向关系子集，不能当整套系统的可靠性。

Apartment 在正负两类查询中各有 81 条因 target/reference 缺失而拒答；Cubicle 各有 46 条。因此很高的负例拒答率，可能大量来自感知失败。正例本来有物体，系统却答不出来，同样是需要保留的失败。

**上限诊断比盲目调阈值更有用。** Apartment 的 17 个合格类别中只有 1 类有严格定位正确的永久对象，严格正确的双端候选对为 0。Cubicle 有 7/18 类，对应 21/149 个可严格双端定位的正例，上限约 14.09%；当前答对 17/149。只改拒答分数，无法跨过候选定位上限。

现有 570 条查询并不等于 570 个独立场景或独立实验样本：它们来自两个场景的任务两两组合，正负例还共享物体和 anchor；负例是方向完全取反，且排除了小于 0.25 m 的主轴边界样本。不能把这一测试描述为完整 absent-object、遮挡、近边界或多实例消歧基准。

## 5. 本次已完成的修正实验

找到的代码缺口：候选 reference 只要与查询词有一个相同 token 就会入选，但 reference 的匹配分数没有乘进最终排序。原式近似：

`target_text_match × target_conf × reference_conf × (0.2 + 0.8 × direction_score)`

实验仅乘上 `reference_text_match`；这还是 token Jaccard，不是 PE 或语言模型。`RelationConfig.score_reference_semantics=True` 才启用，默认 False 保留冻结协议。阈值仍为 0.60，几何、检索、分割、聚类、GT 与 query 分母均不变。

| 相同 0.60 阈值，原版 → 参考物匹配加权 | Apartment | Cubicle |
|---|---:|---:|
| 回答数 | 39 → 31 | 91 → 86 |
| 严格正确关系回答 | 0 → 0 | 17 → 17 |
| 容差正确关系回答 | 16 → 25 | 72 → 72 |
| 容差错误回答 | 23 → 6 | 19 → 14 |
| 容差回答错误率 | 58.97% → 19.35% | 20.88% → 16.28% |
| 全查询回答覆盖率 | 14.34% → 11.40% | 30.54% → 28.86% |
| 负例错误回答 | 0 → 0 | 2 → 2 |
| 双端容差正确且关系冲突拒答的负例 | 14 → 25 | 67 → 67 |

Apartment 是 9 个容差正确正例新增、0 个原正确正例回退；Cubicle 保留全部 72 个容差正确回答，新增拒绝 5 个原来会回答但双端定位错误的正例。后者不是“多拒对了 5 个关系负例”，负例误答仍为 2。

真实案例一：`clean toaster / front_of / soy sauce bottle`，原 reference 为 Tide bottle；加权后选择 soy sauce，自定义容差判定变正确，严格仍未过。

真实案例二：`condiment packets / front_of / mudstone rock`，memory 缺少 mudstone，原来选 quartz rock，分数约 0.998；乘 reference Jaccard 1/3 后约 0.333，拒绝输出。这修正了高分错误答案，但没有找回缺失的参考物。

这些是 **已暴露场景上的事后缓存消融**，不是独立 held-out 或置信度校准结果。不能将容差变化写成严格 Acc@1 提升，也不能据此宣布问题已经解决。

## 6. 拒答消融：能讲什么，不能讲什么

固定原版候选排序，Cubicle 的结果如下：

| 策略 | 答案数 | 严格 / 容差正确 | 负例误答 | 容差回答错误率 |
|---|---:|---:|---:|---:|
| 有有效候选就答，移除方向／歧义／分数门控 | 206 | 21 / 77 | 103 | 62.62% |
| 仅方向＋候选歧义门控 | 99 | 17 / 72 | 2 | 27.27% |
| 原版再加 0.60 分数门控 | 91 | 17 / 72 | 2 | 20.88% |
| 加 reference 匹配分数，仍用 0.60 | 86 | 17 / 72 | 2 | 16.28% |

“有候选就答”不是全查询都答：没有 target/reference 时仍无答案。该对照体现拒答的作用，也保留了拒掉正确答案的代价；原版从 77 个容差正确提议只回答了 72 个，严格正确则从 21 个降到 17 个。

扫描了 0、0.4、0.5、0.6、0.7、0.8、0.9、0.95、1.0，未选择新阈值。Cubicle 原版 0.4～0.8 输出完全一样；提高到 0.9 虽消除两条负例误答，容差正确回答也从 72 降到 61。Apartment 严格候选对为零，拟合严格正确性的校准器没有正样本基础。零回答时 risk 记为 null，不能记成 0 风险系统。

[覆盖率—风险图](../runs/interview-relation-audit-20260909/risk_coverage.png) 同时展示严格和容差口径。这里 risk 是错误答案数 / 输出答案数；coverage 是输出答案数 / 全部冻结查询数。这种联合报告方式与 [selective classification 的风险—覆盖率定义](https://jmlr.org/papers/v11/el-yaniv10a.html)一致，但本项目未实现该论文的统计风险保证。

关系实验口头补充：

> 我发现负例拒答率很高不能说明输出可靠，因此同时统计输出覆盖率、回答错误率和双端定位情况。追踪到 reference 的文本匹配分数未参与排序后，做了固定缓存消融；Cubicle 在保留 72 个容差正确回答的同时，错误回答从 19 个减至 14 个，代价是覆盖率从 30.5% 降到 28.9%。严格正确数没变，场景也不是独立新测试，所以我把它作为修正案例。

## 9. 面试时必须能回答的十个问题

1. 上游已有 PE/SAM，你新增了什么？回答自己的选帧、lifting 约束、关联与评测；不能把预训练模型归为原创。
2. 为什么 mask 与 pointmap 要同网格？解释像素索引意义和 resize/crop/pad 的一致性。
3. 为什么不能把 `world_from_camera` 字段直接当 SE(3)？解释本适配器历史命名、齐次除法与单独 rigid anchor。
4. MAD 在过滤什么？解释三维点到坐标中位数的径向距离，及最小可信点数的作用。
5. complete-link 相比连通分量解决了什么，又损失了什么？用 A–B–C 和 Cubicle FP/FN 数字解释。
6. F1 为何高而中心定位准确率低？讲 pair 分母、标签容差、观测缺失、融合偏移与实例选择。
7. 5/18→7/18 到底比较了什么？讲实际 robust Top-1 与完整 Q1F，不能归因 A2 单项。
8. 关系里的左右相对谁？给出 `delta_anchor = R_anchor.T @ (center_target - center_reference)`，+x 右、+z 前；不是世界坐标默认左右。
9. 98.66% 拒答率为什么不够？讲正例误拒、双端定位、条件 risk 与整体 coverage。
10. 下一步优先做什么？优先提高真正可定位的候选覆盖，纠正 reference 身份与分数；有独立数据后才做校准。
